# Decisions and deviations from the build plan

| # | Decision | Why |
|---|---|---|
| 1 | **Brochures are a shared knowledge base.** Every authenticated user can see and chat over every `ready` document; only the uploader can rename, reprocess or delete. | As specified in the plan; reviewers can use brochures uploaded by the demo account immediately. |
| 2 | **Chat model defaults to the `gemini-flash-latest` alias**, embeddings to `gemini-embedding-001` with `output_dimensionality=768`. Both are env vars. | Model names change often and the Gemini docs host was not reachable from the build sandbox to pin a dated name. The alias always points at the current Flash model. Vectors are L2-normalised client-side because truncated Gemini embeddings are not unit length. |
| 3 | **Embedding dimension is fixed at 768** for every provider. | Switching provider needs no schema change, only a "Reprocess". |
| 4 | **shadcn/ui components were written by hand in shadcn's format** (`components/ui`, `components.json`) on top of the `radix-ui` npm package. | The shadcn registry (`ui.shadcn.com`) was blocked from the build sandbox; the components are the same copy-in source the CLI would generate. |
| 5 | **Inter is loaded from `@fontsource-variable/inter`** instead of `next/font/google`. | Builds do not depend on reaching Google Fonts. |
| 6 | **Frontend uploads to Supabase with XHR** against the same signed-upload endpoint `uploadToSignedUrl` uses, falling back to `supabase.storage.uploadToSignedUrl`. | XHR exposes upload progress events for the progress bar; supabase-js does not. |
| 7 | **`STORAGE_BACKEND=local`** stores PDFs in `backend/uploads` and uploads through `PUT /api/documents/{id}/upload?token=…` (short-lived signed JWT). `experimental.middlewareClientMaxBodySize` is raised to 60 MB so that path works through the Next.js proxy. | Lets reviewers run everything without Supabase (README §7). Production uses direct-to-Supabase uploads. |
| 8 | **Next.js middleware only matches `/chat`, `/documents`, `/login`, `/register`**, never `/api`. | Middleware must not buffer SSE responses or upload bodies. |
| 9 | **SSE fallback**: the chat client automatically retries with `?stream=false` if the stream fails or the response is not `text/event-stream`, and remembers this in `localStorage`. The retry passes `regenerate=true`, so the backend reuses the already-saved user message instead of duplicating it. | The plan requires the non-stream fallback when a proxy buffers or breaks SSE. |
| 10 | **Keyword search ORs the meaningful query words** (`websearch_to_tsquery('english', 'boot or space or creta')`). | `websearch_to_tsquery` ANDs words by default, which almost never matches multi-word sub-queries. |
| 11 | **Conversation titles are the first 6 words of the first message** rather than an LLM call. | Free, instant and deterministic; the plan allows either. |
| 12 | **`LLM_PROVIDER=fake`**: a deterministic offline provider (hashed bag-of-words embeddings, extractive cited answers). | Used by the test suite and lets the app run end to end without any API key. It is not used in production. |
| 13 | **Frontend hosted on Render instead of Vercel** (second web service in `render.yaml`). | A Vercel token was not available for the automated deployment. The architecture is unchanged: the Next.js server rewrites `/api/*` to the backend, so the auth cookie stays first-party. To move to Vercel: import the repo with root `frontend` and the same env vars. |
| 14 | **Unconfirmed uploads older than a day are deleted on startup**, alongside the required re-queue of `queued`/`processing` documents. | Abandoned `pending_upload` rows would otherwise accumulate. |
